# 窗口模式（Dialog Mode）设计规格

## 功能概述

按下指定快捷键后，查询光标附近的单词并弹出对话框。对话框提供候选词按钮、搜索词输入框及辞典 URL 按钮，允许用户跳转到对应词典查询。

---

## 触发方式

### 自动触发

用户处于**快速模式**时，若光标位置与上下文均未发生变化，再次按下快速模式的快捷键（即第二次双击 Option），则自动切换为窗口模式。

### 手动触发（命令/快捷键）

默认不绑定快捷键。用户可通过 Obsidian 系统设置，为「打开窗口模式」命令手动分配快捷键。

### 模式选择设置

在插件设置界面，允许用户指定双击 Option 后触发**快速模式**还是**窗口模式**（默认：快速模式）。

## 组件规格

### 上下文（Context）

| 属性 | 说明 |
|---|---|
| UI 类型 | 文本域（Textarea） |
| 内容来源 | 触发窗口模式时光标所在的上下文，逻辑与快速模式一致 |
| 交互行为 | 用户手动修改内容或在文本域内移动光标时，更新「候选词」按钮；**不**自动调用辞典 URL |
| 尺寸限制 | 控制高度，防止长文本撑开布局；移动端尤其注意 |

### 候选词：もしかして

| 属性 | 说明 |
|---|---|
| UI 类型 | 按钮组（Button group） |
| 内容来源 | 调用与快速模式相同的形态分析 API，获取「辞書形（dictionary form）」 |
| 初始行为 | 弹出窗口后，基于第一个候选词立即填入「検索語」并渲染辞典 URL 按钮 |
| 点击行为 | 将选中按钮对应的单词写入「検索語」输入框，并更新辞典 URL 按钮 |
| 最大数量 | 5 个按钮 |
| 按钮分布 | 前 3 个：API 分析结果；第 4 个：基于浏览器 Segmenter API 获取的光标附近词段原型；第 5 个：反馈按钮（暂不实现） |
| 显示优先级 | 优先展示词组、合成词等通过 Elasticsearch 对词条建立索引的形式；候选单词当前阶段可简单理解为光标附近的「原形」 |

> **暂不实现**：第 4 个（Segmenter API）及第 5 个（反馈）按钮。

### 検索語（Search Word）

| 属性 | 说明 |
|---|---|
| UI 类型 | 单行输入框（Text input） |
| 内容来源 | 由「候选词」按钮写入，或用户手动输入 |
| 同步行为 | 内容变更后，自动更新「辞典 URL 按钮」的目标单词 |

> **暂不实现**：调用 Suggest API 在用户手动输入时提供辅助建议。

### 辞書を引く（Dictionary URL Buttons）

| 属性 | 说明 |
|---|---|
| UI 类型 | 按钮组（Button group） |
| 内容来源 | 插件设置中配置的辞典 URL scheme（与快速模式共用） |
| 初始行为 | 窗口弹出后，焦点默认放在第一个按钮，并**立即调用**该按钮对应的 URL |
| 点击行为 | 使用当前「検索語」填入 URL scheme，跳转到对应词典 |

> **暂不实现**：封装「検索カテゴリ」指定的辞典 URL，允许在设置界面快速添加。

### メモ帳（Notes）

| 属性 | 说明 |
|---|---|
| UI 类型 | 文本域（Textarea）；移动端隐藏，改为底部「メモ」按钮 |
| 默认占位符 | `ここで何かをメモしましょう` |
| 保存时机 | 点击「確認」按钮后，将内容保存到历史笔记 |
| 移动端入口 | 底部操作栏显示「メモ」按钮（位于「確認」左侧），点击后展开文本域或进入笔记编辑流程 |

> iOS 端键盘弹起后无法可靠地自动聚焦，故移动端不自动聚焦メモ帳文本域。

---

## 确认与取消

| 按钮 | 行为 |
|---|---|
| 確認 | 保存メモ内容到笔记，关闭对话框 |
| キャンセル | 丢弃所有未保存内容，关闭对话框 |

---

## 移动端适配

- 默认**隐藏说明性质的文本**（如标签名、提示文字），节省屏幕空间。
- **メモ帳文本域隐藏**：移动端不显示メモ帳文本域，底部操作栏改为「[メモ] [確認] [キャンセル]」三按钮布局，「メモ」按钮位于「確認」左侧。
- 需重点测试长文本上下文时的布局展示，防止文本域撑开页面。
- iOS 端不自动聚焦メモ帳文本域（键盘弹起限制）。
