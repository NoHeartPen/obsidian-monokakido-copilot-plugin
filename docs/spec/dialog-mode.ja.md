# ダイアログモード 設計仕様

## 機能概要

ショートカットキーを押すと、カーソル付近の単語を検索してダイアログを表示します。候補語ボタン・検索語入力欄・辞書URLボタンを提供し、対応する辞書へジャンプできます。

---

## トリガー方式

### 自動トリガー

**クイックモード**使用中に、カーソル位置とコンテキストが変化していない状態で、再度クイックモードのショートカットキーを押した場合（Option を2回ダブルクリック）、自動的にダイアログモードへ切り替わります。

### 手動トリガー（コマンド/ショートカット）

デフォルトではショートカットキーは未設定です。Obsidian のシステム設定から「ダイアログモードを開く」コマンドにキーを割り当てることができます。

### モード選択設定

プラグイン設定画面で、Option ダブルクリック後に**クイックモード**と**ダイアログモード**のどちらを起動するか選択できます（デフォルト：クイックモード）。

## コンポーネント仕様

### 上下文（コンテキスト）

| 項目 | 内容 |
|---|---|
| UIタイプ | テキストエリア |
| コンテンツソース | ダイアログモード起動時のカーソル周辺コンテキスト（クイックモードと同じロジック） |
| インタラクション | 手動編集またはカーソル移動時に「もしかして」ボタンを更新。辞書URLは**自動起動しない** |
| サイズ制限 | 長文テキスト時にレイアウトが崩れないよう高さを制限。モバイル端末で特に注意 |

### もしかして（候補語）

| 項目 | 内容 |
|---|---|
| UIタイプ | ボタングループ |
| コンテンツソース | クイックモードと同じ形態素解析APIで取得した「辞書形」 |
| 初期動作 | ダイアログ表示後、最初の候補語を「検索語」に即時セットし、辞書URLボタンをレンダリング |
| クリック動作 | 選択した候補語を「検索語」入力欄に書き込み、辞書URLボタンを更新 |
| 最大表示数 | 5個 |
| ボタン内訳 | 前3個：API解析結果；第4個：ブラウザ Segmenter API による語段原型；第5個：フィードバックボタン（未実装） |
| 優先表示 | 語句・複合語など Elasticsearch でインデックス化された見出し語を優先表示 |

> **未実装**：第4候補（Segmenter API）および第5候補（フィードバック）ボタン。

### 検索語

| 項目 | 内容 |
|---|---|
| UIタイプ | 一行テキスト入力 |
| コンテンツソース | 「もしかして」ボタンから書き込み、または手動入力 |
| 同期動作 | 内容変更時に「辞書URLボタン」のターゲット語を自動更新 |

> **未実装**：手動入力時に Suggest API でサジェスト候補を表示する機能。

### 辞書を引く（辞書URLボタン）

| 項目 | 内容 |
|---|---|
| UIタイプ | ボタングループ |
| コンテンツソース | プラグイン設定で登録した辞書URLスキーム（クイックモードと共通） |
| 初期動作 | ダイアログ表示後、最初のボタンにフォーカスし、対応する URL を**即時起動** |
| クリック動作 | 現在の「検索語」をURLスキームに埋め込み、対応辞書へジャンプ |

> **未実装**：「検索カテゴリ」を指定する辞書URLのラッパー（設定画面から追加する機能）。

### メモ帳

| 項目 | 内容 |
|---|---|
| UIタイプ | テキストエリア（デスクトップ）；モバイルでは非表示、代わりにフッターに「メモ」ボタンを表示 |
| プレースホルダー | `ここで何かをメモしましょう` |
| 保存タイミング | 「確認」ボタンを押した後、ヒストリーノートに内容を保存 |
| モバイル入口 | フッターの「メモ」ボタン（「確認」の左側）をタップしてメモ入力へ移行 |

> iOS ではキーボード表示後の自動フォーカスが解決できないため、モバイルではメモ帳テキストエリアへのオートフォーカスは実装しません。

---

## 確認・キャンセル

| ボタン | 動作 |
|---|---|
| 確認 | メモ内容をノートに保存してダイアログを閉じる |
| キャンセル | 未保存の内容を破棄してダイアログを閉じる |

---

## モバイル対応

- 説明的なラベルテキストはデフォルトで**非表示**とし、画面スペースを節約。
- **メモ帳テキストエリアを非表示**：モバイルではメモ帳エリアを表示せず、フッターを「[メモ] [確認] [キャンセル]」の3ボタン構成に変更。「メモ」ボタンは「確認」の左側に配置。
- 長文コンテキスト時のレイアウト表示を重点的にテスト。テキストエリアが画面を押し広げないよう注意。
- iOS ではメモ帳テキストエリアへの自動フォーカスは未実装（キーボード表示の制約）。
